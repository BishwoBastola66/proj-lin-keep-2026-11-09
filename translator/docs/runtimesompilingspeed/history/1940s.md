# Computing and Optimization History: The 1940s

## 1. Hardware Architecture & Physical Constraints
The 1940s marked the birth of electronic and electromechanical stored-program digital computers:
* **Representative Systems**: Zuse Z3 (1941, electromechanical relays), Harvard Mark I (1944, electromechanical), ENIAC (1945, vacuum tubes, hardwired switchboards/patch cables), EDVAC (von Neumann design, 1945 report), Manchester Baby / SSEM (1948, first stored-program electronic computer), EDSAC (1949, Cambridge).
* **Storage Mechanisms**:
  * Mercury acoustic delay-line memory (EDSAC, EDVAC): Bits stored as sound pulses traveling through tubes of liquid mercury; access was strictly sequential and latency-dependent.
  * Williams-Kilburn tubes (Manchester Baby): Electrostatic CRT storage (~1024 bits per tube).
  * Magnetic drums: Rotating cylinders with ferromagnetic coating; access time tied directly to cylinder rotational speed (thousands of milliseconds per revolution).
  * Vacuum tube flip-flops: Extremely fast but consumed massive power, generated high heat, and occupied enormous physical volume.
* **Word Sizes & Instructions**: 32-bit to 40-bit words, fixed-point arithmetic only. Floating-point arithmetic had to be laboriously simulated via software routines.

---

## 2. What Was Expensive?
* **Storage Capacity**: Primary memory was counted in tens to hundreds of words. The Manchester Baby had 32 words of 32 bits (128 bytes total). EDSAC had 512 35-bit words.
* **Component Reliability**: Vacuum tubes had mean time between failures (MTBF) measured in hours. Long-running calculations were frequently interrupted by tube burnouts.
* **Input/Output**: Punched cards (Hollerith 80-column) and paper tape were mechanical and orders of magnitude slower than vacuum-tube clock cycles (e.g., 100 kHz clock).

---

## 3. What Was Slow?
* **Memory Access**: Acoustic delay lines and magnetic drum access required waiting for the pulse or sector to circulate to the read head (latency up to several milliseconds).
* **Instruction Cycle Times**: Addition took hundreds of microseconds (e.g., EDSAC addition ~1.5 ms, multiplication ~6 ms).
* **Division and Complex Functions**: Multi-step iterative loops taking seconds of machine time.

---

## 4. What Programmers Optimized Manually
* **Instruction Packing & Space Minimization**: Squeezing programs into 32–512 words. Every single word saved meant data could fit. Programmers reused data memory locations as temporary instruction targets.
* **Optimal Latency Coding (Drum / Delay Line Interleaving)**: On magnetic drums and acoustic delay lines, an instruction at location $N$ took a certain number of cycles to execute. By the time it finished, the drum had rotated past location $N+1$. Programmers placed the *next* instruction at location $N+k$ so it arrived under the read head exactly when the CPU was ready for the next fetch. This was the earliest manual instruction scheduling.
* **Subroutine Sharing**: The "Wheeler Jump" (invented by David Wheeler on EDSAC in 1949) established the first calling convention using self-modifying code to plant the return address.

---

## 5. What Compilers Optimized Automatically
* **Zero**: Compilers did not exist. Programs were written in pure binary, octal, or plugboard wiring.
* The closest precursor was Wheeler’s assembly routines (Initial Orders on EDSAC, 1949), which converted symbolic characters to numeric memory addresses during tape load.

---

## 6. Hardware Limitations Imposed on Software
* **Lack of Index Registers**: Arrays and tables had to be accessed by *self-modifying code*—the program literally wrote new address bits into its own load/store instruction words at runtime before executing them.
* **Lack of Relocation**: Addresses were absolute physical addresses. Relocating a routine required re-punching the paper tape or manually recalculating all address constants.
* **Absence of Memory Protection**: Any errant jump or store overwritten instructions or destroyed the operating system routines (if any existed).

---

## 7. Breakthrough That Changed Compiler Design
* **Von Neumann Architecture (First Draft of a Report on the EDVAC, 1945)**: The concept that instructions and data reside in the same address space and share the same representation. This allowed programs to manipulate other programs as data—the foundational requirement for assemblers, compilers, and loaders.

---

## 8. Breakthrough That Changed Runtime Design
* **The Stored-Program Concept & Subroutines (Wheeler, Wilkes, Gill, 1949–1951)**: David Wheeler demonstrated that common subroutines (sine, square root, division) could be stored in a library of paper tapes and linked into programs dynamically by the Initial Orders loader.

---

## 9. Ideas That Survived
* The Stored-Program Concept (instructions as data).
* Call/Return subroutine abstractions.
* Instruction scheduling to mask memory latency (conceived here for drum rotation, later revived for pipelines and memory hierarchies).

---

## 10. Ideas That Disappeared
* **Acoustic Delay-Line Memory**: Replaced by magnetic core memory in the 1950s.
* **Manual Drum Interleaving**: Obsoleted by random-access memory (RAM).
* **Ubiquitous Self-Modifying Code for Array Indexing**: Made obsolete by hardware index registers (Manchester Mark 1 "B-lines", 1949).

---

## 11. Ideas That Returned Decades Later Under a Different Name
* **Latency-Aware Instruction Scheduling**: Placing instructions at rotational offsets to hit drum heads exactly is mathematically identical to pipelined instruction scheduling (filling branch delay slots and load latency slots in 1980s RISC processors).
* **Self-Modifying Code**: Returned in the 1990s as **Just-In-Time (JIT) Compilation**, dynamic runtime patching, and inline caches.
