# Computing and Optimization History: The 1980s & The RISC / VLIW Revolution

## 1. Hardware Architecture & Physical Constraints
* **Representative Systems**:
  * IBM 801 (John Cocke, pioneer RISC).
  * Berkeley RISC I/II (David Patterson, Carlo Séquin).
  * Stanford MIPS (John Hennessy).
  * Sun SPARC (1987).
  * MIPS R2000 / R3000 (1986/1988).
  * Multiflow TRACE (1987, Josh Fisher, first commercial VLIW).
  * Intel 80386 / 80486 (CISC survival via pipelining).
* **Technological Shifts**:
  * **VLSI (Very Large Scale Integration)**: An entire 32-bit CPU fitted onto a single silicon chip (e.g., 25,000 to 100,000 transistors).
  * **Pipelined Execution**: The classic 5-stage RISC pipeline: Fetch (IF), Decode (ID), Execute (EX), Memory (MEM), Writeback (WB). Every instruction executed in an effective 1 cycle throughput ($CPI \approx 1$).
  * **Load/Store Architectures**: Arithmetic operations operate exclusively on registers; memory access is restricted to explicit load and store instructions.
  * **On-Chip and Split Caches**: Separate Level 1 instruction (L1I) and data (L1D) caches to avoid Harvard/von Neumann fetch-store bus contention.

---

## 2. What Was Expensive?
* **Silicon Transistor Budgets**: Putting complex microcode and hardware decoders onto a single chip left no room for caches or pipelined execution units. RISC spent transistors on large register files and caches instead of microcode ROMs.
* **Pipeline Stalls (Hazards)**:
  * Structural hazards (hardware resource conflicts).
  * Data hazards (read-after-write dependencies requiring forwarding or stalling).
  * Control hazards (branch decisions not known until the execute or decode stage, wasting cycles).

---

## 3. What Was Slow?
* **CISC Multi-Cycle Instructions**: Microcoded instructions on Intel x86 or DEC VAX took 5–20 cycles per instruction ($CPI > 5$).
* **Uncached Memory Access**: CPU clock speeds began increasing faster than DRAM access times (early warning signs of the Memory Wall).
* **Branch Delays**: In a pipelined CPU, resolving a conditional branch cost 1 to 3 wasted pipeline bubbles.

---

## 4. What Programmers Optimized Manually
* **Branch Delay Slot Filling**: On MIPS, SPARC, and early RISC, the instruction immediately following a jump or branch was executed unconditionally before the branch took effect (the "delayed branch"). Assembly programmers had to find a useful, non-dependent instruction to stick into the delay slot, or insert an empty `NOP`.
* **Memory Alignment**: Accessing 32-bit words at non-4-byte-aligned addresses caused hardware trap faults or took double cycles.

---

## 5. What Compilers Optimized Automatically
The 1980s was the golden age of compiler/hardware co-design. RISC was fundamentally an architecture *for* optimizing compilers:
* **Graph-Coloring Register Allocation (Chaitin, 1981, 1982; Briggs, 1989)**: Gregory Chaitin published the complete algorithm transforming register allocation into graph $K$-coloring. If degree $< K$, push on stack; if all degrees $\ge K$, pick a variable to spill based on loop nesting depth and loop count. Preston Briggs later refined this with optimistic coloring (allowing previously marked spills to be colored if adjacent neighbors share colors).
* **Instruction Scheduling & Pipeline Hazard Avoidance (Hennessy & Gross, 1983)**: Reordering instructions within basic blocks using DAGs (Directed Acyclic Graphs) and critical path weighting to separate load instructions from the instructions that use their results, eliminating load-use stalls.
* **Branch Delay Slot Scheduling**: Automatically moving independent instructions before the branch into the delay slot, or executing the target instruction speculatively with the "annulling" branch bit.
* **Trace Scheduling & VLIW (Josh Fisher, 1981; John Ellis, 1985 "Bulldog" Compiler)**:
  * Fisher recognized that instruction-level parallelism (ILP) inside a single basic block is strictly limited (~2–3 instructions).
  * Trace scheduling looked across basic block boundaries, concatenating frequent execution paths into a "trace".
  * The compiler scheduled instructions across the entire trace simultaneously into wide VLIW words (e.g., 7 or 14 parallel operations per cycle) and inserted "compensation code" along off-trace exit/entry edges to maintain correctness.
* **Register Windows vs. Compiler Register Allocation**:
  * Berkeley RISC and Sun SPARC introduced hardware **Register Windows** (136+ physical registers shifting a window of 8 in, 8 local, 8 out on function calls).
  * Stanford MIPS, IBM 801, and John Hennessy argued that hardware register windows wasted silicon area and increased context switch latency. They proved that Chaitin's graph coloring register allocation with software calling conventions produced equivalent or superior register utilization without the hardware penalty. History validated Hennessy's view.

---

## 6. Hardware Limitations Imposed on Software
* **Exposed Pipeline Latencies**: Early RISC architectures (like MIPS I) had no hardware interlocks for load delays. If the compiler failed to insert an independent instruction or a `NOP` after a `LW`, the CPU read stale data from the register file. The compiler was legally responsible for pipeline correctness.

---

## 7. Breakthrough That Changed Compiler Design
* **Hennessy & Patterson’s Quantitative Approach (1989–1990)**:
  $$\text{Execution Time} = \frac{\text{Instructions}}{\text{Program}} \times \frac{\text{Clock Cycles}}{\text{Instruction}} (CPI) \times \frac{\text{Time}}{\text{Clock Cycle}}$$
  Proved that minimizing instruction count at the cost of high CPI was a losing strategy. Compilers emitting more simple instructions with $CPI = 1$ ran significantly faster.

---

## 8. Breakthrough That Changed Runtime Design
* **C Calling Conventions on Register Architectures**: Standardizing passing the first 4 to 8 function arguments directly in registers (`$a0`–`$a3` in MIPS, `%o0`–`%o5` in SPARC), avoiding memory writes for subroutine invocations.

---

## 9. Ideas That Survived
* Chaitin-Briggs graph coloring register allocation (still the bedrock of GCC, LLVM, and modern production backends).
* Load/Store architecture separation.
* Pipelined instruction scheduling.
* Calling conventions passing arguments in registers.

---

## 10. Ideas That Disappeared
* **Exposed Hardware Delay Slots**: Delayed branches and delayed loads proved to be disastrous for backward compatibility when pipelines grew deeper in the 1990s. Later ISAs eliminated branch delay slots.
* **Hardware Register Windows**: Abandoned by almost all post-1990 ISAs due to register spill traps on deep recursion and massive context-switch overhead.
* **Pure Static VLIW for General-Purpose Computing**: VLIW failed for general-purpose workloads because static compile-time schedules could not adapt to unpredictable cache misses.

---

## 11. Ideas That Returned Decades Later Under a Different Name
* **Trace Scheduling (Fisher)**: Returned in the 2000s inside JIT compilers as **Trace-based JIT compilation** (TraceMonkey, PyPy, Dynamo).
* **VLIW Wide Execution Words**: Returned in digital signal processors (DSPs) and modern **GPU compute engines** / **tensor processing units (TPUs)**, where execution is completely deterministic and memory access is streaming.
