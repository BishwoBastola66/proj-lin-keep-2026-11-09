# Computing and Optimization History: The 2000s & The Multicore / LLVM Revolution

## 1. Hardware Architecture & Physical Constraints
* **Representative Systems**: Intel Pentium 4 (NetBurst architecture, 31-stage pipeline, reaching ~3.8 GHz), AMD Athlon 64 / Opteron (2003, integrated memory controller, AMD64 64-bit architecture), Intel Core 2 Duo / Quad (2006, Conroe architecture, abandonment of NetBurst), Intel Nehalem (2008, integrated memory controller, QuickPath Interconnect, on-die L3 cache).
* **The Historic Turning Point (2004–2005)**:
  * **The Breakdown of Dennard Scaling**: For 30 years, Robert Dennard’s 1974 scaling law dictated that as transistors shrank, power density remained constant because operating voltage scaled down proportionally with gate dimensions. Around 90nm/65nm, quantum leakage currents prevented further voltage reduction below ~1V.
  * **The "Power Wall"**: The Pentium 4 hit over 130 Watts at 3.8 GHz. Pushing clock frequencies to 5–10 GHz would have generated power densities comparable to a nuclear reactor core.
  * **Herb Sutter’s Manifesto (2005)**: *"The Free Lunch Is Over: A Fundamental Turn Toward Concurrency in Software"*. CPU vendors could no longer double single-thread clock speeds every 18 months. Performance scaling shifted from raw frequency to **chip-level multiprocessing (multi-core)** and **SIMD vectorization**.

---

## 2. What Was Expensive?
* **Inter-Core Synchronization & Cache Coherence**: Cross-core communication via the MESI/MOESI bus protocols. Locking a shared variable invalidated cache lines across all CPU cores.
* **Thermal Throttling**: Processors dynamically downclocked if instruction power density exceeded thermal design power (TDP).
* **Compiling Enormous C++ Codebases**: Header-heavy template metaprogramming (Boost, STL) caused severe compilation speed slowdowns, creating the demand for faster, modular compiler infrastructures.

---

## 3. What Was Slow?
* **Single-Threaded Software on Stalled Clocks**: Code that could not parallelize stopped getting automatically faster with each new CPU generation.
* **Non-Vectorized Math Loops**: Executing floating-point operations one scalar element at a time on an x87 stack while 128-bit SIMD execution units sat completely idle.
* **Locks and Mutex Contention**: Traditional operating system mutexes and heavy context switches crippled throughput under multi-threaded concurrency.

---

## 4. What Programmers Optimized Manually
* **Multi-Threaded Partitioning**: Decomposing monolithic tasks across OS threads using POSIX pthreads, OpenMP, or Intel Threading Building Blocks (TBB).
* **Manual SIMD Intrinsics**: Writing explicit `_mm_load_ps`, `_mm_add_ps`, `_mm_mul_ps` intrinsics using SSE/SSE2.
* **False Sharing Avoidance**: Padding per-thread data structures to 64-byte cache line boundaries to prevent cores from constantly invalidating each other's L1 caches.

---

## 5. What Compilers Optimized Automatically
* **LLVM: A Modular Compiler Infrastructure (Chris Lattner & Vikram Adve, 2004)**:
  * Prior compilers (GCC) were tightly coupled monolithic codebases where frontend, middle-end, and backend were difficult to separate.
  * LLVM defined a clean, strongly typed, language-independent Static Single Assignment (SSA) Intermediate Representation (LLVM IR).
  * Lattner and Adve decoupled the compiler into independent reusable libraries: language frontends emitted LLVM IR, middle-end passes transformed IR into optimized IR, and target backends lowered IR to machine code. This architecture enabled whole-program link-time optimization (LTO) and dynamic JIT execution with identical passes.
* **Auto-Vectorization (Loop SIMD Vectorization)**: Compilers (GCC, Intel ICC, LLVM) began automatically identifying parallelizable inner loops, unrolling them by vector factors (e.g., 4 x 32-bit floats for SSE2), and emitting packed SIMD instructions.
* **Superword-Level Parallelism (SLP) Vectorization (Larsen & Amarasinghe, 2000)**: Finding isomorphic independent operations within a single basic block and grouping them into SIMD instructions without requiring loops.

---

## 6. Tracing JITs vs. Method JITs
The mid-2000s witnessed intense experimentation with **Tracing JIT Compilers**:
* **HP Dynamo (Bala, Duesterwald, Santhanam, 2000)**: Dynamic native binary translator that identified hot instruction loops at runtime and compiled optimized straight-line traces.
* **TraceMonkey (Gal et al., Mozilla, 2009) & PyPy**:
  * Traced the dynamic execution path through nested function calls and branches of an interpreter.
  * Assumed that loops run the exact same path with the exact same types.
  * Emitted linear machine code with zero branching, protected by guard conditions.
* **Why Tracing JITs Failed for General-Purpose Web/App Workloads**:
  * Tracing worked brilliantly on numeric benchmarks with tight loops.
  * In real-world code with branching control flow, execution repeatedly failed trace guards, leading to "trace explosion" and constant deoptimization ("trace tree aborts").
  * By 2011, major engines (V8, SpiderMonkey) abandoned pure tracing in favor of **Method-based Tiered JITs with Polymorphic Inline Caching**.

---

## 7. Multicore Memory Models & Concurrency Formalization
* **Java 5 Memory Model (JSR-133, Manson, Pugh, Adve, 2004)**: Prior to 2004, multi-threaded memory visibility was loosely defined. JSR-133 formally defined the *happens-before* relationship, volatile read/write semantics, and safe publication guarantees for concurrent threads.
* **C++ Memory Model Foundations (Hans Boehm, 2005)**: Hans Boehm published *"Threads Cannot be Implemented as a Library"*, proving that concurrency semantics must be part of the core language and compiler specification; otherwise, standard compiler transformations (register spilling, loop invariant motion) introduce silent race conditions and data corruption. This led directly to the C++11 and C11 memory models.

---

## 8. Breakthrough That Changed Compiler Design
* **LLVM IR and Modular Pass Managers (2004)**: Democratized compiler research and industry compiler creation. Any new language could target LLVM IR and immediately gain state-of-the-art SSA optimizations and codegen for x86, ARM, and PowerPC.

---

## 9. Breakthrough That Changed Runtime Design
* **Lock-Free Data Structures & Work-Stealing**: Runtimes moved away from centralized job queues and mutexes toward Chase-Lev lock-free work-stealing deques for multicore task scheduling.

---

## 10. Ideas That Survived
* Modular IR-driven compiler architecture (LLVM).
* Multi-core task parallelism & lock-free work stealing.
* Formally defined language memory models (*happens-before*, acquire-release atomics).
* Loop and SLP auto-vectorization.

---

## 11. Ideas That Disappeared
* **Deep 30+ Stage Pipelines for Clock Scaling (NetBurst)**: Replaced by wider, shorter (12–14 stage) out-of-order pipelines with higher IPC.
* **Pure Tracing JIT Compilers for General Dynamic Languages**: Superseded by tiered method JITs.

---

## 12. Ideas That Returned Decades Later Under a Different Name
* **Trace-Based Dynamic Optimization**: Reappeared inside **eBPF JIT compilers** and profile-guided binary optimizers (BOLT) where straight-line execution traces guide block layout.
