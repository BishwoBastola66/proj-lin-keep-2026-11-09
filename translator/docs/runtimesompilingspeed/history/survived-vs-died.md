# Historical → Modern → Rubix Matrix: What Survived vs. What Died

This central matrix maps every major historical architectural, compiler, and runtime discovery from the 1950s to 2026, documenting why it succeeded or failed, how modern hardware transformed its assumptions, and whether it applies to Rubix.

---

## 1. The Global Comparative Matrix

| Historical Idea | Originating System & Era | Original Purpose | Why It Died or Changed | Modern Hardware Change (2026) | Modern Status / Interpretation | Rubix Applicability |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Index Register Frequency Allocation** | IBM FORTRAN I (Haibt, 1957) | Spilling variables to core memory when registers $< 3$ | Replaced by global graph coloring | CPU registers grew to 16 (x86) / 32 (ARM64) | Basis of Profile-Guided Optimization (PGO) and hot-path block layout | **APPLICABLE**: Prioritize register allocation and loop hoisting in inner loops. |
| **Control Flow Graphs & Dominators** | Fran Allen & John Cocke (1969) | Formal representation of program structure for global optimization | Survived universally; became foundation of SSA | High IPC multi-issue pipelines require deep branch analysis | Foundational representation in LLVM, GCC, and HotSpot | **APPLICABLE**: Rubix CFG and dominator trees are essential for dead code elimination and loop analysis. |
| **Hardware Stack Architectures** | Burroughs B5000 (1961) | Direct hardware execution of Algol activation records | **DIED**: Prevented compiler register allocation; far slower than register files | Modern OoO CPUs rely on register renaming (PRF); stacks are purely in-memory | Dead on physical CPUs; survives inside virtual bytecodes (Wasm, JVM) | **NOT APPLICABLE** for physical machine code; **APPLICABLE** for portable stack bytecode. |
| **Graph-Coloring Register Allocation** | Gregory Chaitin (IBM, 1981) | Formulate register allocation as graph $K$-coloring | Survived; Briggs added optimistic coloring | PRF sizes grew to 400+ physical registers; register spills cost 50+ ns if missing cache | Universal in production AOT compilers (LLVM, GCC) | **APPLICABLE**: Use Chaitin-Briggs for AOT release builds; Linear Scan for fast JIT builds. |
| **Hardware Delay Slots** | Berkeley RISC / MIPS (1981) | Keep 5-stage pipeline busy during branches without stalls | **DIED**: Disastrous for backward compatibility when pipelines deepened | Modern 16-stage pipelines use dynamic branch predictors (TAGE) | Completely abandoned in modern ISAs (ARM64, RISC-V omit delay slots) | **NOT APPLICABLE**: Never emit architectural delay slots. |
| **Pure Static VLIW / Trace Scheduling** | Multiflow TRACE (Fisher, 1984) | Squeeze 28 operations per cycle into wide instruction words | **DIED**: Compilers could not predict DRAM cache miss latencies, freezing the pipeline | Modern CPUs use out-of-order execution windows (ROB) to absorb memory stalls | Survived in DSPs (Hexagon) and specialized AI accelerators (Groq) | **POTENTIALLY APPLICABLE**: Use trace scheduling for code layout (branch fall-through), not hardware bundling. |
| **Automatic Data Structure Selection** | SETL (Jack Schwartz, 1975) | Compiler chooses physical data structures from abstract sets | **DIED**: Global dataflow analysis had $O(N^3)$ complexity; mainframes had tiny memory | Memory access is 200 cycles slower than ALU; cache-friendly contiguous arrays yield 50x speedups | Re-emerging in database optimizers and typed array specializations | **APPLICABLE (NEW SYNTHESIS)**: Implement `ADSS-CacheBlock` for collection specialization. |
| **Dynamic Inline Caching & PICs** | Self-91 (Chambers & Ungar, 1991) | Eliminate indirect dynamic message dispatch in OOP | Survived universally; became the foundation of modern dynamic speed | Modern CPUs have large indirect branch predictors, but direct jumps remain 3x faster | Standard in V8, HotSpot, SpiderMonkey, Julia | **APPLICABLE**: Essential for polymorphic method and interface dispatch in Rubix. |
| **Deoptimization (Uncommon Traps)** | Urs Hölzle (Self, 1992) | Speculatively inline methods under dynamic assumptions | Survived universally; enables speculative AOT/JIT optimizations | Speculative execution is standard; software deoptimization provides safety | Universal in HotSpot C2, V8 TurboFan | **APPLICABLE**: Allows aggressive speculative inlining with graceful fallback to interpreter. |
| **Hardware Register Windows** | Sun SPARC / Berkeley RISC (1981) | Accelerate subroutine calls by shifting hardware register banks | **DIED**: Excessive silicon area; severe register spill trap latency on deep recursion | Calling conventions passing arguments in registers with caller/callee save rules won | Abandoned in all modern 64-bit architectures | **NOT APPLICABLE**: Use standard register-based calling conventions (System V AMD64 / AAPCS64). |
| **EPIC / Static Speculation (ALAT)** | Intel Itanium IA-64 (1994) | Replace out-of-order hardware with compiler-directed bundling and speculation | **DIED**: Crushed by AMD64; compilers could not tolerate dynamic memory latency | Modern x86-64 and ARM64 processors discovered ILP dynamically at lower cost | Dead in general CPUs; survives in GPU PTX compilation | **NOT APPLICABLE** in hardware; **APPLICABLE** in software predication (`CMOV`). |
| **Pure Tracing JIT Compilers** | TraceMonkey (Gal & Eich, 2009) | Compile hot loops into branchless linear machine code | **DIED**: Suffered trace tree explosion and deopt aborts on real-world branching code | Modern TAGE branch predictors handle branched method code without trace fragility | Abandoned in major JS engines in favor of Method SSA JITs | **EXPLICITLY REJECTED**: Rubix must use method SSA compilation, not tracing loops. |
| **Transparent Binary Translation** | Transmeta Crusoe / CMS (2000) | Translate CISC x86 to low-power VLIW via dynamic ROM JIT | **DIED commercially**: Stuttered on cold start; crushed by Intel Pentium M | Large caches and fast OoO cores make dynamic translation near-native | Resurrected brilliantly in Apple Rosetta 2 | **POTENTIALLY APPLICABLE**: Portable bytecode-to-native execution cache. |
| **Modular SSA Intermediate Representation** | LLVM (Lattner & Adve, 2004) | Decouple compilers into reusable libraries centered around typed SSA IR | Survived universally; won the compiler infrastructure war | Multi-core compilation requires scalable ThinLTO passes | Foundation of modern language toolchains (Rust, Swift, Julia, Zig) | **APPLICABLE**: Rubix internal architecture mirrors clean IR lowering (UIR / AIR / MIR). |
| **Bump Arena Allocation in Compilers** | Bonwick / Clang `BumpPtrAllocator` | Eliminate malloc/free lock contention and fragmentation in compilers | Survived universally; mandatory for sub-second build times | 64-byte cache lines and memory bandwidth dominate compilation speed | Standard in Go, Clang, Rustc | **APPLICABLE (CRITICAL)**: Bump arena for AST and IR nodes yields immediate 20% compile-time speedup. |
| **Scalable Parallel Linking** | ThinLTO (2016) / Mold (2021) | Eliminate single-threaded linker bottlenecks on multi-core CPUs | Survived universally; revolutionized developer build loops | 64+ core servers and NVMe SSDs demand high multi-threading and memory mapping | Standard across hyperscaler CI/CD pipelines | **APPLICABLE**: Fast internal linker / ELF synthesizer saturating cores. |
| **Post-Link Binary Layout Optimization** | BOLT (Panchenko et al., 2019) | Reorder basic blocks and split cold code after linking using LBR profiles | Survived universally; adopted across Meta, Google, Apple | Large binaries overflow 32 KB L1I cache; front-end stall is dominant bottleneck | Standard in production Clang/Rustc release toolchains | **APPLICABLE**: Basic block fall-through alignment in Rubix machine code emitter. |
| **Linear / Affine Types for Memory Safety** | Philip Wadler (1990) / Sisal (1992) | Guarantee single-owner references at compile time to mutate arrays in-place | Survived; reincarnated in Rust | DRAM copy latency is the single greatest bottleneck in modern computing | The defining breakthrough of 2010s systems programming | **APPLICABLE**: Rubix borrow checker / escape analysis for zero-allocation mutations. |
