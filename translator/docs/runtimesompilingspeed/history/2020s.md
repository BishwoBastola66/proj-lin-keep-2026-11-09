# Computing and Optimization History: The 2020s & Hardware Heterogeneity

## 1. Hardware Architecture & Physical Constraints
* **Representative Systems**:
  * Apple Silicon M1–M4 (Ultra-wide 8-wide decode out-of-order frontend, unified system memory architecture with massive bandwidth >400 GB/s, on-die Neural Engine and matrix coprocessor AMX).
  * AMD Zen 3 / Zen 4 / Zen 5 (3D V-Cache: stacking 64 MB SRAM die directly on top of the CCD to deliver 96 MB L3 cache per CCD; AVX-512 with dual 256-bit or full 512-bit datapaths without downclocking).
  * Intel Alder Lake / Raptor Lake / Arrow Lake (Hybrid architecture: "Golden Cove / Lion Cove" Performance-cores paired with "Gracemont / Skymont" Efficient-cores; hardware Intel Thread Director).
  * ARM Neoverse N2 / V2 (Cloud hyperscaler CPUs: AWS Graviton3/4, Ampere Altra).
  * RISC-V RV64GCV (Ratification of the RISC-V Vector Extension v1.0).
  * Compute Express Link (CXL 2.0 / 3.0): PCIe Gen5/Gen6 coherent memory pooling and device interconnects.
* **Technological Shifts**:
  * **Unified High-Bandwidth Memory**: Apple Silicon showed that placing LPDDR5 memory chips directly on the processor substrate with 128-bit to 512-bit bus widths eliminated CPU-GPU PCIe copy bottlenecks.
  * **3D Stacked SRAM (3D V-Cache)**: Overcoming the Memory Wall by packing unprecedented amounts of low-latency L3 cache (up to 96 MB per CCD, 192 MB per dual-CCD socket) directly above CPU execution cores.
  * **Asymmetric Multiprocessing on Desktops and Servers**: Schedulers must dynamically allocate threads across heterogeneous cores with radically different IPC, vector widths, and cache topologies.

---

## 2. What Was Expensive?
* **Cross-Core / Cross-Socket Memory Latency vs Bandwidth**: DDR5 bandwidth increased, but CAS latencies in absolute nanoseconds remained stubbornly at ~50–70 ns. Cache misses remained devastating.
* **Heterogeneous Core Scheduling Jitter**: Scheduling a compute-bound worker thread onto an E-core (Efficient-core) can cut throughput by 3x–4x compared to running on a P-core.
* **PCIe Bus Transfers for Accelerators**: Offloading small computations to discrete GPUs incurred PCIe round-trip latency costs ($10\text{--}20\ \mu\text{s}$) that erased all acceleration benefits unless batched over massive data arrays.

---

## 3. What Was Slow?
* **Linkers in Development Cycles**: Even with SSDs, traditional linking remained the single biggest developer bottleneck on large software codebases.
* **Memory-Bound Workloads on Narrow Caches**: Database joins, graph algorithms, and compilers stalled waiting on LLC cache misses.

---

## 4. What Programmers Optimized Manually
* **Mold Linker Adoption (Rui Ueyama, 2021)**: Migrating from GNU ld / LLD to Mold, a hyper-parallel linker designed to saturate all CPU cores and memory channels, linking large binaries in hundreds of milliseconds instead of tens of seconds.
* **Core Affinity & Thread Pinning**: Binding real-time and compute threads exclusively to P-cores with large L3 caches, avoiding OS scheduler migration to E-cores.
* **Cache-Resident Algorithms**: Sizing working sets to fit entirely within the 96 MB L3 cache of AMD 3D V-Cache processors.

---

## 5. What Compilers Optimized Automatically
* **AutoFDO and Continuous Production Profiling (Google, Meta)**:
  * Running sampling profilers (using hardware Performance Monitoring Units - PMUs) on production fleet servers with near-zero overhead (<1%).
  * Feed profiles directly back into automated CI/CD compiler pipelines to rebuild binaries optimized for real-world user traffic patterns.
* **Vector-Length Agnostic (VLA) Compilation for Scalable Vectors**: Compilers began targeting ARM SVE and RISC-V RVV, generating code that does not hardcode a register width (128-bit vs 256-bit vs 512-bit), allowing a single compiled binary to run natively across diverse hardware vector lengths.
* **Compiler Self-Optimization Pipelines**: Integrating PGO and post-link optimization (BOLT) directly into production toolchain builds for Clang, Rustc, and Go, reducing compilation times by 10%–20%.

---

## 6. Breakthrough That Changed Compiler Design
* **Scalable Vector Extensions (ARM SVE / RISC-V Vector)**: Shifting vector compilation from fixed-width strip-mining to dynamic hardware vector-length configuration (`vsetvli`), decoupling compiler intermediate representation from hardware register widths.

---

## 7. Breakthrough That Changed Runtime Design
* **eBPF (Extended Berkeley Packet Filter) in the Linux Kernel**: Runtimes and system profilers can safely execute sandboxed, JIT-compiled bytecode inside the kernel space at native speed without kernel modules, enabling zero-overhead observability and high-performance network packet processing.

---

## 8. Ideas That Survived
* Mold-style high-concurrency linkers.
* Automated continuous production profiling (AutoFDO).
* 3D stacked cache architectures.
* Heterogeneous CPU scheduling co-designed with hardware thread directors.
* Scalable vector programming models.

---

## 9. Ideas That Disappeared
* **Fixed Monolithic Die Scaling**: Leading-edge silicon moved decisively to multi-die chiplets and advanced packaging (TSMC CoWoS, Intel EMIB).

---

## 10. Ideas That Returned Decades Later Under a Different Name
* **Vector-Length Agnostic Execution**: Seymour Cray’s 1976 vector length register concept returned as the modern **ARM SVE** and **RISC-V Vector (RVV)** programming model, replacing rigid SIMD instructions.
