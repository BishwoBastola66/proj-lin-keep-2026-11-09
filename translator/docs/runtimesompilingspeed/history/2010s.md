# Computing and Optimization History: The 2010s & Scalable Compilers / Modern JITs

## 1. Hardware Architecture & Physical Constraints
* **Representative Systems**: Intel Sandy Bridge / Haswell / Skylake (AVX, AVX2, AVX-512), AMD Zen (2017, chiplet architecture revolution), ARM Cortex-A15 / Cortex-A53 (big.LITTLE), ARM Cortex-A72 / Neoverse (server ARM debut), Apple A7–A12 (64-bit ARM desktop-class mobile chips), NVIDIA Kepler / Pascal / Volta (GPGPU and Tensor Cores).
* **Technological Shifts**:
  * **AVX / AVX2 / AVX-512**: Vector register widths widened to 256 bits (ymm) and 512 bits (zmm) with 3-operand non-destructive instruction encoding and Fused Multiply-Add (FMA3).
  * **AMD Chiplets & Infinity Fabric (Zen)**: Moving from monolithic dies to modular Core Complex Dies (CCDs) connected to a central I/O Die (IOD), dramatically lowering manufacturing cost and multiplying core counts up to 64 cores per socket.
  * **Mobile & Energy-Efficient Computing Dominance**: Smartphones demanded high performance per watt; heterogenous big.LITTLE architectures paired high-IPC performance cores with low-power efficiency cores.

---

## 2. What Was Expensive?
* **AVX-512 Thermal Throttling / Frequency Drops**: On early Intel Skylake-X and Xeon processors, executing wide 512-bit vector instructions triggered high current draw ($dI/dt$), causing the hardware to downclock the entire CPU core by several hundred megahertz, sometimes making AVX-512 code *slower* than AVX2!
* **Cross-CCD / NUMA Latency**: In chiplet architectures, communicating across CCDs incurred a 40–80 ns interconnect latency penalty over the Infinity Fabric compared to intra-CCX L3 cache access.
* **Whole-Program Link-Time Optimization (LTO) Resource Exhaustion**: Traditional monolithic LTO required loading all LLVM IR into a single process memory space at link time. On multi-million-line applications (Chrome, Firefox, Linux kernel), monolithic LTO consumed over 64 GB of RAM and took hours to compile.

---

## 3. What Was Slow?
* **Linkers**: GNU `ld` and `gold` were single-threaded and struggled with the massive metadata generated by modern C++ and Rust templates.
* **Dynamic Language Execution Without Type Feedback**: Pure interpreters or non-optimizing JITs could not keep up with client-side single-page applications.

---

## 4. What Programmers Optimized Manually
* **Cache-Conscious Data Layout (Data-Oriented Design / SoA vs AoS)**: Transitioning from Arrays of Structures (AoS: `struct Particle { float x, y, z, mass; } particles[N]`) to Structures of Arrays (SoA: `struct Particles { float x[N], y[N], z[N], mass[N]; }`) to enable flawless SIMD auto-vectorization and cache line streaming.
* **NUMA Memory Allocation**: Pinning worker threads to specific CPU sockets and allocating local socket memory via `numactl` or `mbind`.

---

## 5. What Compilers Optimized Automatically
* **ThinLTO: Scalable Whole-Program Optimization (Teresa Johnson, Mehdi Amini, David Li, 2016)**:
  * Solved the monolithic LTO scalability bottleneck.
  * During the compile step, each translation unit emits a compact global module summary (call graph, symbol references, function size).
  * At link time, a lightweight thin linker analyzes the global summary and decides cross-module inlining and dead-symbol elimination without loading full function IR.
  * The actual optimization and code generation passes are then distributed across parallel worker threads. ThinLTO provided 95%+ of monolithic LTO's performance benefits with build times scaling linearly across all CPU cores.
* **Post-Link Binary Optimization: BOLT (Facebook / LLVM, Maksim Panchenko et al., 2018–2019)**:
  * Profiled running binaries in production using hardware performance counters (Linux `perf` with LBR - Last Branch Record).
  * Ingested the final ELF executable, disassembled it, and rearranged basic blocks and function layouts to maximize instruction cache (L1I) and instruction TLB (iTLB) hit rates.
  * Demonstrated that binary reordering after linking could yield another 5% to 15% end-to-end CPU throughput improvement over `-O3` and PGO.
* **V8 TurboFan & Sea-of-Nodes IR (Google, 2014–2017)**:
  * Replaced the Crankshaft compiler in Chrome’s V8.
  * Implemented an SSA "Sea-of-Nodes" IR (originating from Cliff Click’s HotSpot Server compiler design) combining data-flow and control-flow dependencies into a unified graph.
  * Enabled advanced speculative optimizations, hidden-class type feedback, and seamless deoptimization.
* **GraalVM & Truffle (Oracle Labs, Thomas Würthinger et al., 2012–2018)**:
  * Truffle enabled language implementers to write a simple AST interpreter; Graal automatically applied **Partial Evaluation** (Futamura projections) to compile the interpreter and program into native code competing with hand-tuned C compilers.
* **WebAssembly (W3C, 2017)**:
  * A fast, portable, sandboxed binary instruction format designed for near-native execution speed in web browsers and servers.

---

## 6. Breakthrough That Changed Compiler Design
* **ThinLTO (2016)**: Proved that whole-program cross-module optimization can scale to distributed build environments and dozens of cores without memory exhaustion.
* **LLVM LLD Linker (Rui Ueyama, 2016)**: Multi-threaded drop-in linker that was 3x to 5x faster than GNU gold, transforming developer iteration times.

---

## 7. Breakthrough That Changed Runtime Design
* **Modern Concurrent Garbage Collection (ZGC, Shenandoah, Go Concurrent GC)**:
  * Traditional GCs caused multi-second stop-the-world pauses on multi-gigabyte heaps.
  * Modern low-pause collectors introduced load barriers, colored pointers, and concurrent thread evacuation, reducing GC pause times from hundreds of milliseconds to under 1 millisecond.

---

## 8. Ideas That Survived
* ThinLTO (standard in production builds across Google, Apple, Meta, Rust compiler).
* Sea-of-Nodes IR in modern JIT compilers (V8 TurboFan, GraalVM).
* Multi-threaded high-throughput linkers (LLD, Mold).
* Post-link optimization with hardware branch profiles (BOLT).
* Sub-millisecond concurrent garbage collection.

---

## 9. Ideas That Disappeared
* **Heavyweight Static Monolithic LTO on Large Projects**: Replaced by ThinLTO.
* **Aggressive Vector Downclocking**: Modern CPUs no longer cripple base frequencies for vector workloads.

---

## 10. Ideas That Returned Decades Later Under a Different Name
* **Futamura Projections (1971)**: Theoretical principle that compiling an interpreter specialized with a program yields a compiled binary; fully realized in production 45 years later by Graal/Truffle.
