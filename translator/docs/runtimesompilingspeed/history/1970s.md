# Computing and Optimization History: The 1970s & Mathematical Optimization Theory

## 1. Hardware Architecture & Physical Constraints
* **Representative Systems**: DEC PDP-11 (1970, 16-bit CISC, orthogonal addressing modes, Unix cradle), DEC VAX-11/780 (1977, 32-bit complex instruction set with memory-to-memory operations), Cray-1 (1976, vector registers, vector chaining), IBM System/370 (virtual memory standard).
* **Technological Shifts**:
  * **MOS Semiconductor Memory**: Replaced magnetic core memory (Intel 1103 DRAM chips, 1970), dropping memory access times to ~200–300 ns.
  * **Paging and Virtual Memory**: Standardized memory isolation and large virtual address spaces (e.g., VAX 4 GB virtual address space).
  * **Cray-1 Vector Supercomputing**: 8 vector registers (each holding 64 64-bit words) with pipelined vector execution units and **vector chaining** (feeding the output of a vector multiply directly into a vector add before the full vector operation finished).

---

## 2. What Was Expensive?
* **Microcode ROM Space**: CISC architectures (VAX) attempted to "close the semantic gap" by creating hundreds of complex instructions (`INDEX`, `POLY`, `CALLS`, `CRC`) directly implemented in expensive microcode control stores.
* **CISC Instruction Decoding**: Complex multi-byte variable-length instructions with multiple memory addressing modes took multiple clock cycles just to decode.
* **Compiler CPU and Memory Footprint**: Compilers were memory-constrained (often running on 64 KB PDP-11s); whole-program global optimization was considered too slow for everyday software engineering.

---

## 3. What Was Slow?
* **Memory Subroutines vs Register Operations**: Calling functions on VAX using `CALLS` saved all mask-indicated registers to memory, making procedure calls on VAX notoriously slow (~10–20 µs) compared to simple RISC register-based jumps.
* **Complex CISC Instructions**: In practice, executing a sequence of 3 simple instructions was often faster than executing 1 complex microcoded CISC instruction that performed the equivalent operation.

---

## 4. What Programmers Optimized Manually
* **Memory vs. Register Variables in C**: The `register` keyword was introduced in C (Ritchie, 1972) because compilers were unable to reliably decide which variables belonged in registers across procedure scopes.
* **Vector Loop Formatting**: On Cray-1, programmers manually restructured nested loops into flat loops with lengths matching multiples of 64 to maximize vector register utilization.
* **Manual Strength Reduction and Bitmasking**: Writing bitwise shifts (`>> 1`) instead of division by 2.

---

## 5. What Compilers Optimized Automatically
The 1970s transformed compiler optimization into a unified mathematical discipline:
* **The Lattice Data-Flow Framework (Gary Kildall, 1973)**: Gary Kildall published *"A Unified Approach to Global Program Optimization"* at the inaugural ACM POPL 1973. He proved that data-flow analyses (constant propagation, available expressions, reaching definitions) could all be formalized as monotonic transfer functions over semilattices with fixed-point iteration.
* **Monotone Data Flow Frameworks (Kam & Ullman, 1976–1977)**: John Kam and Jeffrey Ullman established the algebraic properties and convergence bounds of Kildall's iterative data-flow algorithms.
* **Interval Analysis & Reducible Flow Graphs (Robert Tarjan, 1974; John Cocke, 1970)**: Tarjan used depth-first search and dominator trees to prove efficient linear and almost-linear time graph decomposition algorithms for loop analysis.
* **Loop-Invariant Code Motion (LICM) and Induction Variables (Ken Kennedy, 1971–1972)**: Formalized node-splitting, loop nests, and automatic hoisting of loop-invariant calculations outside loop headers.
* **Optimal Code Generation for Trees (Aho & Johnson, 1976)**: Alfred Aho and Stephen Johnson introduced dynamic programming algorithms (the Sethi-Ullman / Aho-Johnson algorithm) to generate minimal instruction sequences using the minimum number of registers for expression trees.
* **Precursors to Graph-Coloring Register Allocation (John Cocke & Gregory Chaitin, IBM Research, late 1970s)**: Cocke and Chaitin recognized that register interference could be modeled as an undirected graph, where registers are colors. If the graph is $K$-colorable (where $K$ is the number of machine registers), no spills are required.
* **IBM PL.8 Compiler (John Cocke et al., 1975–1979)**: Experimental optimizing compiler for the IBM 801 (the first RISC machine). PL.8 demonstrated that a compiler could optimize code so well that a simple instruction set easily outperformed complex microcoded architectures.

---

## 6. Hardware Limitations Imposed on Software
* **CISC Semantic Mismatch**: Compilers struggled to utilize complex instructions like `INDEX` or `POLY` because the exact conditions under which they could be safely emitted were too specialized. Compilers generated simpler subsets of CISC ISAs, rendering the microcoded complexity wasted silicon.

---

## 7. Breakthrough That Changed Compiler Design
* **Kildall’s Semilattice Framework (1973)**: Replaced ad-hoc pass-specific optimization heuristics with a mathematically rigorous, provably correct, terminating fixed-point calculation.
* **IBM 801 / PL.8 Co-Design (1975)**: Proved that hardware and compiler must be designed as a unified system: strip hardware down to simple, single-cycle instructions and let a global optimizing compiler do the heavy lifting.

---

## 8. Breakthrough That Changed Runtime Design
* **C Calling Convention & Unix System Call Model**: Simplified stack discipline where caller passes arguments on stack, registers `r0`/`r1` return values, and small system call stubs transition directly to kernel space via software interrupt (`trap`/`sys`).

---

## 9. Ideas That Survived
* Semilattice data-flow analysis (still the foundation of modern dataflow passes).
* Dominator tree algorithms (Lengauer-Tarjan 1979 algorithm is still used in LLVM today).
* Loop-invariant code motion (LICM).
* Aho-Johnson instruction selection principles (extended later into bottom-up rewrite systems like BURG).
* Graph coloring for register allocation.

---

## 10. Ideas That Disappeared
* **CISC "Semantic Gap" Hardware**: Microcoded complex instructions intended to mirror high-level language semantics (e.g., Algol/COBOL specific machine instructions).
* **Manual `register` Keyword Necessity**: Modern optimizing compilers completely ignore the C `register` keyword and allocate registers mathematically.

---

## 11. Ideas That Returned Decades Later Under a Different Name
* **Cray Vector Registers**: Returned in modern SIMD and scalable vector architectures: AVX-512, ARM SVE/SVE2, and RISC-V Vector Extension (RVV), where vector registers and dynamic vector lengths mirror Cray's original vector design.
* **Kildall’s Semilattice Fixed Points**: Extended in modern SSA form into **Sparse Conditional Constant Propagation (SCCP)** (Wegman & Zadeck, 1991).
