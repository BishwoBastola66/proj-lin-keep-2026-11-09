# Rubix Whole-Repository Stub & Implementation Reality Ledger

## 1. Executive Summary & Objective

This ledger serves as the authoritative, uncompromised accounting of all claims, implementations, emulations, and stubs across the Rubix ABI, compiler middle-end, runtime, and platform abstraction layers.

Following the principle: **"A test is not evidence of implementation unless removing the implementation causes the test to fail,"** each component is classified under strict implementation states:
- `REAL`: Implemented with native hardware instructions or OS kernel primitives; observable at runtime; mutation causes failure.
- `PARTIAL`: Real mechanism implemented for primary host target (x86-64 Linux); foreign target or edge-case handling lowered to bridge or table descriptors.
- `EMULATED`: Functional reference model implemented in user-space logic rather than native kernel/hardware primitives.
- `UNSUPPORTED`: Explicitly acknowledged architectural non-support; rejected safely without silent corruption.
- `FALSE-GREEN`: Passes tests by returning expected status or hash without performing the physical operation.
